## 1. 先要决定的（阻断级）

### 1.1 工作树里有 1129 个「假改动」——换行符污染

**证据**

```
$ git status --porcelain | wc -l          → 1129
$ git diff --ignore-all-space -- .editorconfig | wc -l   → 0
$ git diff --ignore-all-space --numstat | wc -l          → 356
$ git config --get core.autocrlf           → （空，未设置）
```

也就是说：1129 个改动里，绝大多数是 CRLF↔LF 的整文件重写，**忽略空白后只剩 356 个文件有实质差异**，其中还有一批是 `scripts/mixamo/**/input.json` 被清空（`0 +457` 这种）。

**影响**：现在 `git add -A && git commit` 会产出一个 1129 文件的提交，review 不进去，回滚也回不进去。

**建议做法**（按顺序，别跳）

1. 先加 `.gitattributes`（`* text=auto`，二进制文件标 `binary`），再 `git add --renormalize .`，让换行符差异一次性归零并单独成一个提交；
2. 然后才提交真实改动；
3. 提交前用 `git diff --ignore-all-space --stat` 复核，确认只剩预期文件。

**这一条不做，后面所有改动都没法交付。**

## 2. 未解决的功能问题（按影响排序）

### 2.1 loft 房间画面被房间几何糊住（不是「她变黑了」）

这是被误诊最久的一条。**证据链**：

1. **不是她**：加 `?hidechar=1` 把模型 `visible=false`，那团黑**原样还在**（[208](../shots/hanami-port/208-loft-hidechar.png)）。所以是房间几何，不是材质/光照/法线问题。
2. **不是「人-镜头」这条线被挡**：取景探针 `probe=want=1.63 1.93beyond gap=0.31 at 0.6,1.4,1.8 n=0.9,0.0,0.5 pPlane8_plafond_0`——射线在 1.93 m 处打到 **`pPlane8_plafond_0`（法语 plafond = 天花板）**，比想要的机位只远 0.31 m，于是被判为「没被挡」。
3. **镜头前方五向射线也不近**：`occl=c:3.10 l:2.74 r:open u:3.39 d:1.07`（全打在 `environment` 上）。镜头站在屋里，四面 3 m 内没有近物。

**结论**：镜头正好贴在**吊顶/斜屋顶的下沿**，那块深色平面从下往上看占掉画面上半；而这个房间是「盒子切片」，有些面直接缺失，缺面处看到的就是背景深灰。两个因素叠加，画面就成了黑的。

**还没验证的一步**（本轮工具调用被打断，没做完）：她出生点 `(0,0)` 是不是正落在某件家具里。用 `?dev=1&room=cozy-loft-room&gazedebug=1&walk=0.6,1.0` 走开再截图即可判断。

**修法候选**（都没有实现，不要以为已经修了）

- 调这个房间的 `spawn` / `camera.eye`，让她和镜头都避开吊顶下沿；
- 给 `frameToRoom` 加一条判据：**镜头前方 5 条射线里如果 ≥3 条在 1.5 m 内命中，就换机位**（现在只判「人到镜头」这一条线，判不出「贴着镜头侧面的墙」）；
- 或者接受现实：这个房间素材不适合放人，从清单里撤掉。

### 2.2 `frameToRoom` 的候选循环诊断读数与代码不符（已回退，仅留档）

给候选机位加诊断时，读数一直是 `n1`（只试了第一个机位），但代码里 5 个候选、没有任何一条路径会只跑一个，加 try/catch 也没抓到异常。

**处理**：当时想做的改动（绕着人换角度的机位）**已完整回退**，没有留在代码里。这条只是提醒——如果以后又要动 `frameToRoom`，先把这个读数问题搞清楚，否则会拿假读数做判断。

### 2.3 `transitions.json` 只能做到「族级」映射

已落地的是按类别给值（运行时徽章 `fade=` 可证）：

| Overte 源状态 | 淡入 | 缓动 | 我们这边 |
|---|---|---|---|
| `idleToWalkFwd` | 0.267 s | linéaire | 步态、起步/收步 |
| `turnLeft` / `turnRight` | 0.500 s | easeInOutQuad | `world-turn-*` |
| seated 族中位数 | 0.267 s | easeInOutQuad | `world-sit-*` |
| `talk` / `talk02..04` | 0.667 s | easeInOutQuad | 说话 |
| idle 族中位数 | 0.500 s | easeInOutQuad | 待机 |

**做不到的原因**：Overte 的片段 id（`walkFwdNormal_c`）和 Hanami 的命名（`world-walk`）之间没有对照表，素材里也没留。逐状态映射需要这张表，凭空猜就是编。

### 2.4 手臂限位只做了「屈曲」，没做 swing / twist

膝盖（单向 [-150°, +3°]）和手肘（[-3°, +150°]）都在运行（徽章 `kj=` / `ej=` 可证）。但**肩关节的摆动/扭转**没做，Hanami 的 `jointLimits.ts` 里有对应逻辑。

影响：目前所有片段都不会把肩掰到离谱的角度，所以「看不见」；一旦接入用户自定义动作就会露。

### 2.5 57 个手型状态没接线

`transitions.json` 里 165 个状态有 57 个对不上任何片段，全是手型状态（`rightHandGraspOpen`、`leftIndexPointClosed`、`userAnimA/B`……）。lobe 这边有手部静止姿势（`stageHands.ts`），但和状态图没连。

### 2.6 `emotionMap` 只做了「反应时触发表情」，没做「状态→默认表情」

Hanami 是根据状态持续给表情（待机=平静、被戳=惊讶、坐下=放松）。我们这边表情只在 `react()` 时短暂出现、随后衰减，站着的默认表情是固定的。

### 2.7 `next build` 从未绿

10 个既存 lint 错误（`no-explicit-any`、未使用变量之类），不是移植引入的。`tsc --noEmit` 和 `next dev` 都不受影响，但交付前得清掉。

### 3.2 触摸设定接线（头/上半身/肚子/手和手臂/腿/脚）

以前「设置 → 触摸」配的动作**在有房间时完全无效**：`viewer.handleClick` 一旦发现已经铺了房间就直接 `navigator.react(area)`，那是一个写死的反应池（点头/举手/摇头），设置里配的表情和动作根本没被读。表现为「点哪儿都只触发一句对话/一个默认反应」。

现在改成两层，先读设置、再退回世界那套：

| 层 | 触发 | 播什么 | 为什么 |
|---|---|---|---|
| 1 | 该部位在设置里有动作 | `clipId` → 动作库里那条真实 `.vrma`（经 `navigator.playTouchClip`，带 `busyUntil` 看门狗）；老数据 `motion` → 17 个旧预设 | 设置面板里能选的片段和舞台动作面板是同一套素材 |
| 2 | 该部位没配 / 坐着 / 动作和片段都空 | 仍然是 `navigator.react`（站姿池 + 坐姿池） | 坐着播站姿片段会把她从椅子上拉起来；空配置也得有反应 |

配套改动：

- **区域拆细**：`TouchAreaEnum` 新增 `Foot`（脚掌 + 脚趾骨），`mapBoneNameToTouchArea` 补上 `UpperChest`（以前点锁骨一带什么都不触发）；`getClosestBone` 参与判定的骨骼加了 `UpperChest`/`LeftToes`/`RightToes`。左栏现在七项：头部 / 上半身 / 肚子 / 手和手臂 / 腿 / 脚 / 臀部（`locales` 里 `touch.area.*` 跟着改名，`foot` 只补了 zh-CN / zh-TW / en-US，其余语言回落中文）。
- **选择器换成动作库**：`AddOrEdit` 的「动作」下拉改成「动作库真实片段（按分类分组、循环片段带 ↻）+ 旧预设」，用 `motionPresetMap` 的老配置照样能读能存（值上带 `clip:` / `preset:` 前缀区分）。走路/转身两类（`locomotion`/`transition`）不给选——那些片段带位移，原地播就是滑步。
- **语言模型设定从设置左栏移出**（`useCategory.tsx`）：这条线没接 LLM，留着只会让人以为改了会生效。`/settings/llm` 路由还在，需要时能直接访问。
- **默认数据**：脚给了一条 `clipId=shake` + 惊讶（素材里没有「被踩到脚」这种片段，摇头顶一下）。

已知不完美：

- 骨盆（`Hips`）表面那一点常常被判成「肚子」——裙子在髋和脊柱之间是连续的一片，最邻近骨骼会挑到 `Spine`。想分开得按网格 UV 分区，成本不划算。
- 走位途中点她：这一次不演（`playTouchClip` 直接返回），否则原地片段会让脚在原地滑。
- 坐着时仍然走坐姿反应池，设置里的站姿片段不生效（这是故意的，见上）。

证据：`326`（七个部位逐点真点，日志 `[touch] <部位> → preset=… / clip=…`）、`328`（脚的片段正在播）、`329`（左栏只剩「通用设置 / 触摸设定」）、`330`（七个部位）、`332`/`333`/`334`（编辑弹窗与动作库下拉）、`335`→`336`（在设置里保存后回舞台，脚仍然是 `clip=shake`，说明表单→store→运行时这条链是通的）。

### 3.3 底栏：按钮移到右侧，中间加输入框（含发送 / 语音）

原来四颗按钮居中排在底栏，现在移到**右侧**，中间空出来的位置给了输入框（带发送按钮和语音按钮）。

**这个框是「替她说一句」，不是聊天。** 后台没有任何模型（项目约定不接 LLM / ASR / TTS），所以：

| 操作 | 行为 |
|---|---|
| 打字 + 回车 / 点发送 | 输入框上方弹出她的台词气泡；同时播动作库里 `talking` 分类的循环片段（`idle-talking*`）；两者时长一致，按字数估（`0.16 s/字`，1.6~12 秒） |
| 说完 | 气泡自己淡掉，片段由 `busyUntil` 看门狗收回待机 |
| 语音按钮 | 走**浏览器自带**语音识别（Chrome / Edge 的 `webkitSpeechRecognition`）。识别结果只填进输入框，发不发由你决定；正在听时输入框边框红色呼吸 |

已知边界（都实测过或明确未验）：

- **她不会回答**：你说一句，她照着说一遍，仅此而已。
- **嘴型不跟你的字对齐**：播的是录制好的「说话待机」片段，没有 TTS 就没有逐音节口型。
- **语音识别只在浏览器里跑**：不给麦克风权限会直接说「没有麦克风权限」；不支持该 API 的浏览器会直说「这个浏览器不带语音识别」。我这里跑的是无头浏览器（没有麦克风、权限被拒），所以**「真的说话 → 识别成文字」这一段没验过**，只验到「点下去会请求麦克风、被拒时给的是明确原因」。
- 她正在走位时按发送：**气泡照出，动作不播**（原地片段会让她边滑边说话）。
- 锁上移动锁不影响说话（`haltAndStand` 只管走路）。

**默认收起，点了才拉开**：静止时只有 188px 一小截（「说点什么…」+ 麦克风），不挡画面；点它（任何位置都算）→ 240ms 过渡拉到 620px，露出完整提示语和发送键。收回的三种情况：

| 触发 | 说明 |
|---|---|
| 点框外面 | 挂在 `document` 的 `pointerdown` 上判断，因为舞台 canvas 会拦 `pointerdown` 默认行为（拖镜头要用），点 3D 画面时输入框**根本不会触发 blur** |
| Esc | 清空并收回 |
| 有文字 / 正在听 | **不收**——打字打到一半框自己缩走是最烦的交互 |

发送后焦点还给输入框（点的是发送按钮，input 会失焦），接着写下一句不用再点一下。她的台词气泡不跟着收缩：气泡是 `width: max-content`，收起态也完整显示。

布局：`Stage/style.ts` 的 `.docker` 改成 `justify-content: center` + 操作按钮绝对定位贴右下（左右对称才真的居中）；宽度不够时（<640px）改成上下两行、按钮居中换行。输入框和右边操作按钮**同高 48px、同圆角 24**，展开最大宽 620px，并按 `max(200px, min(620px, 100% - 620px))` 收窄，保证 840px 宽的舞台也不会压到右边按钮。

证据：`360`（1280 布局）、`361`（发送后气泡 + `[touch] clip=idle-talking loop=true hold=1.76s`）、`363`（回车发送 + 长句 `hold=4.48s`）、`362`/`364`（语音按钮：权限被拒时给明确原因，改动后复测仍正常）、`368`（800px 不重叠）、`369`（560px 改两行）、`373`/`375`（48px 高、620 宽，和按钮同高）、`376`（默认收起）、`377`（点击拉开）、`381`（点画面收回）、`382`（收起态气泡完整）、`383`（600px 窄屏收起）。

### 3.4 操作条：移动锁（触摸交互右边那颗锁）

想把镜头对好、或者只是让她站那儿看一会儿的时候，点地面就会把她挪走。所以加一颗锁：锁上之后**一切「让她换位置/换姿势」的入口**都关掉。

| 锁上之后 | 行为 |
|---|---|
| 点地面 | 不寻路、不走（日志 `[click] locked → ignore`，位置读数一直不动） |
| 悬停桌椅 | 不再出那颗「去坐下」的箭头 |
| 点箭头 / 点座面 | 不坐下（`goSit` 与 `sitAt` 两道都挡） |
| 自己起身闲逛 | 停（`[wander]` 不再触发；站着的待机小动作照旧，那不是位移） |
| 正走到一半时按锁 | 立刻停住并回站姿待机（`haltAndStand()`：清路径 → 解走路保护 → 顶站姿 idle） |
| 点她身体 | **仍然有触摸反应**——锁的是「把她挪走」，不是「不让碰」 |

不锁的：镜头随便转、触摸设定照常、坐着的不会被拽起来（锁不是「立刻回位」）。

实现位置：开关在 `store/character`（`moveLocked`，会持久化，刷新后保持，否则锁好了刷新就散了）；`viewer.setMovementLocked()` 负责同步到 `viewer`（点击/悬停）与 `StageNavigator`（走位/坐下/闲逛）；导航创建时会把当时的锁状态带过去（房间比挂载晚加载，不然锁会丢）。

证据：`340`/`342`（未锁：浅底开锁图标）、`343`/`344`（已锁：实心关锁图标 + tooltip「移动已锁定（点击解锁）」）、`349`（真点按钮：气泡「已锁定：点地面和桌椅不会再让她动了」）、`341`（锁着点地面：`[click] locked → ignore`，`still@0.00,0.00` 全程不动）、`345`（锁着 `afk=4` 16 秒：一次 `[wander]` 都没有）、`346`（锁着点头：`[click] locked → body` + `[touch] head → preset=…`，触摸没被连带关掉）、`347`（解锁后点地面：`floor` → `walk@` → 到达）、`348`（锁着 `seatauto`：找到座位、点了、`[click] locked → ignore`，没坐下去）、`350`/`351`（走到一半按锁：`walk@1.22,0.25 path=34` → 立刻 `still@1.42,0.71 clip=idle.vrma` 并原地不动）。

### 3.5 对话：回复 / galgame 字幕 / 左侧历史浮窗

输入框现在是「发起对话」：**你发一句 → 她回一句**，回复以**大字台词显示在输入框正上方**（galgame 那种存在感），历史留在左边半透明浮窗里。

**先说清楚一件事：后台没有模型。** 回复是 `src/libs/dialogue/reply.ts` 里按关键词从池子里挑的现成句子：

| 输入里有什么 | 她回什么 |
|---|---|
| 你好 / 嗨 / 在吗 | 打招呼的短句 |
| 你是谁 / 名字 / Diva | 自我介绍 |
| 累 / 困 / 熬夜 | 劝你歇一下 |
| 唱 / 歌 / 跳舞 | 老实说现在只会站着说话 |
| 好看 / 喜欢 | 道谢 |
| 吃 / 饿 / 夜宵 | 她不吃东西 |
| 为什么 / 怎么 / 吗 / ？ | 直说答不了、没接模型 |
| 再见 / 晚安 | 告别 |
| 测试 / 占位 | 固定三句（自检用，专门看分段效果） |
| 都没命中 | 中性短句（「嗯。我在听。」这类） |

为了避免让人误以为「她真的懂了」，界面上三处都标了：浮窗右上角常驻「占位回复」小标、第一次回复时弹一次「后台没有接模型：她现在是按关键词挑的占位回复」、空历史里也写着同一句话。

链路（换真模型时只改第一步）：

1. `placeholderReply(你说的)` → 得到一条完整回复文本
2. `pushUser` / `pushAssistant` 写进 `store/dialogue`（历史，`localforage` 持久化，上限 80 条）
3. `splitSegments(回复)` → 按句末标点切成一句句（太短的并到下一句、太长的按逗号再切）
4. `playSegments(句子[])` → 逐句 `setSubtitle` 每句停 `0.9~6 秒`（按字数，0.18 s/字），整段说完清空；同时按**整段总时长**起一次 `talking` 动作片段（不是每句起一次，否则句间会抽一下）
字幕的位置试过两轮：先是在输入框上方一小条（14px，太保守）；改成屏幕正中大字后，字够大了但挡住她，最终**回到输入框正上方**。当前：`font-size: clamp(26px, 3.2vw, 46px)`、600 字重、白字 + 深色垫底 + 文字阴影；没有名字小标。

**一句的完整节奏：打字 → 停 3 秒 → 渐变消失 → 下一句。** 数字都在 `src/libs/dialogue/typing.ts`（组件和播放器共用，免得两处不同步）：

| 参数 | 值 | 说明 |
|---|---|---|
| `CHAR_MS` | 55ms | ≈18 字/秒，再快就看不出在打 |
| `START_DELAY_MS` | 70ms | 起手空档，字不是「啪」地出现 |
| `PAUSE_MS` | `。！？`240 `，`130 `…`200 | 标点额外停顿，读起来有断句 |
| `HOLD_MS` | **3000ms** | 打完停下让人看清 |
| `FADE_MS` | 450ms | 渐变退场，和 CSS `transition: opacity 450ms` 对齐 |

淡出是「先挂淡出样式、等过渡跑完再清字符串」——顺序反了就没有动画可看。整块（含深色垫底）一起淡掉，不是只淡字。

**留白是固定预留的**：台词块 `min-height: 150px`（窄屏 96px）+ `align-items: flex-end`，所以台词出现/消失、长句短句变化时**输入框不会上下跳**，字始终贴着预留区底部（离输入框最近），上面那一截就是给长句的余量。

浮窗留完整历史，可「清空」。

**历史窗口的形态（最后定的）**：不是把左边占满的长条——那样太抢画面。现在是一张 **340px 宽的可拖动小卡片**，表头右上一枚**钉子**决定它怎么显示：

- **钉住（默认）**：卡片常显。但**鼠标不在附近时，边框 / 底色 / 模糊 / 阴影 / 表头全部淡掉，画面上只剩气泡浮着**——不挡画面，也不用去点开
- **钉住 + 悬停**：卡片外观和表头（钉子、清空）一起回来，可以拖动、清空、取消钉住
- **取消钉住**：收成一枚很淡的圆把手（`opacity: .34`，没有底色），鼠标放上去才展开

细节：

- 面板 `border-radius: 22px`、`max-height: min(56vh, 470px)`（超了内部滚动），底色 66% + `blur(18px)`
- 气泡是聊天样式：**你从右来**（浅色 `rgb(255 255 255 / 82%)`、深字），**她从左来**（深色 `rgb(0 0 0 / 48%)`、白字），字号 16px，靠「贴角小圆角」（`6px`）区分气泡尾巴方向
- 外观撤掉时面板整体 `pointer-events: none`，只有**气泡和空状态文字**还能吃鼠标——所以空白处点得到地面，而「把卡片叫回来」只要把鼠标移到任意一个气泡上
- 按住把手可以拖到任意位置，位置和钉子状态一起存 `localStorage`（`vidol-chat-dock-position`，`{x, y, pinned}`，越界会被夹回屏幕内；旧版只存坐标时按「钉住」算）
- 窄屏（<900px）整个挂件不显示

> 位置/钉子状态的持久化**没有截图验证**：截图用的无头浏览器每次都是全新上下文，所以这一条要你在自己浏览器里拖一下、刷一次才算数。

一处踩过的坑：浮窗最早用 `opacity: .62` 做半透明，结果**字也跟着透**——白底白字对比度实测只有 1.70:1（截图工具的 lint 直接报了）。改成底色带 alpha + `backdrop-filter`，字保持不透明。

证据：`450`（钉住 + 鼠标不在：**只剩两个气泡浮在墙上**）、`451`（钉住 + 悬停：卡片和钉子回来）、`452`（点钉子取消钉住后：只剩一枚极淡的圆把手）、`453`（取消钉住 + 悬停：卡片又展开，钉子变成「未钉」）、`454`（鼠标移到气泡上就能把卡片叫回来）、`446`（最早的空态把手）、`441`（空状态卡片）、`442`（两个气泡：你说的话在右、她的在左）、`443`（拖到中间后的位置 + 面板跟着走）、`390`（最早的整条浮窗版本，留作对照）、`410`（台词在输入框正上方，63px 那版）、`411`（收起态：胶囊 188px，台词仍满宽）、`420`/`421`（无名字标 + 46px + 固定留白）、**`431`（录屏 + ffmpeg 抽帧：`motion-sequence.png` 看整段节奏，`fade-strip.png` 每 100ms 一帧看清「满亮 → 半透明 → 更淡 → 清空 → 下一句开始打」）**、`423`（逐字打字过程 0–4.3s）、`424`（600px 窄屏，抓到打字中的「后」）、`396`（整段说完字幕清空、历史仍在）。

**没验的**：历史跨刷新是否真的还在——截图用的无头浏览器每次都是全新上下文，这条要在你自己的浏览器里刷一下才算数。

## 3.7 换房竞态：切到温馨阁楼时镜头钻进头发

**症状**：页面刚打开、默认房间还在下载的时候，从心形菜单点「温馨阁楼」，场景铺出来了，但镜头贴在脑后（画面被一整块黑色头发占满，见 `462`/`463`，等 6 秒也不恢复）。

**根因（已实测确认，不是猜）**：两次 `loadEnvironment` 同时在跑。默认房间（`japanese-classroom`）先发起、后完成，它完成时把**自己**的房间和机位写了进去，把用户刚选的那间顶掉；那一版机位是按教室的墙距算出来的，套在阁楼里就是 0.4 m 贴脸。

**改法**：`viewer.ts` 加一个自增令牌 `envLoadToken`。`loadEnvironment` 进门前领号，`scene` / `model` 两段 `await` 之后各验一次号，号不是最新的直接退出、不往场景里放东西；`unloadEnvironment`（空舞台）和 `loadStage`（PMX 舞台）也会把号往前推，让正在下载的房间作废。

**取证**：给两处退出点临时加了一行 `console.error('[env] 丢弃过期房间加载 …')`，用「打开页面 700 ms 后点心 → 选阁楼」的时序跑，控制台确实出现了 `丢弃过期房间加载 japanese-classroom`（`486` 的报错就是它）——说明竞态真的存在、也确实被这一版挡下来了。取证后日志已删掉（正常路径不该往控制台报错）。

**修完的样子**：`484`（700 ms 时点阁楼）、`485`（300 ms 时点阁楼）、`487`（房间就绪后再切）都是干净的正脸构图；`488` 是切回动漫教室的回归对照，没有变差。

> 仍然**没验**的：宅在阁楼里坐下时取景仍偏挤（`489` 里 `sit=nearest` 那次其实没坐下，只是镜头近了一点）；换房后「刷新还记得这间」依旧没在真浏览器里验过。

## 4. 联调钩子（全部在 `?dev=1` 后面）

| 参数 | 作用 |
|---|---|
| `room=<id>` | 直接铺房间（清单 `/environments/manifest.json`） |
| `gazedebug=1` | 左上角读数：`clip=` 当前片段、`fade=` 这一刀用了多少秒/什么曲线、`kj=`/`ej=` 限位触发次数、`eNow=` 肘角、`seat=` 坐姿、`cam=` 机位、`probe=` 取景探针 |

| `hidechar=1` | 把模型藏起来（判断画面里的东西是角色还是房间） |
| `walk=x,z` / `sit=nearest` / `wander=1` / `activity=<id>` | 走位、坐下、闲逛、指定活动 |
| `turntest=<deg>` / `fidget=1` / `react=head\|arm\|body` | 转身、坐姿小动作、坐姿点击反应 |
| `clip=<vrma 名>` / `look=x,y,z` / `emotion=<表情>` | 单段动作、看向、表情 |
| `hackknee=<deg>` / `hackarm=<deg>` / `nolimits` | 强掰关节验限位 |
| `noik` / `nomerge` / `mark=1` / `click=x,y` | 关 IK / 关网格合并 / 点击标记 / 模拟点击 |
| `touchprobe=1` | 让骨骼自己指出七个触摸部位的屏幕位置（打不到网格会在日志里标 `(miss)`），再逐点真点一下，验「哪个部位 → 播哪条设定动作」 |
| `touchonly=<部位>` | 只反复点一个部位（`foot`/`head`…），用来截「动作正在播」的那一帧 |
| `lock=1` / `lock=0` | 直接把移动锁设成某一边（锁会持久化，验收时要能翻回来），同时打开点击日志 |

忘了 `?dev=1` 前缀，整套读数会**静默失效**——这是最容易踩的坑。
